# Safety boundaries

- Do not request display-required power behavior. Windows should be able to turn off the display and apply its lock policy.
- Respect explicit user sleep, shutdown, restart, lid-close policy, critical battery policy, and Windows power policy.
- Keep leases bounded and bind them to process identity, including process creation time. A PID alone can be reused.
- Default to AC power. The current development CLI requires explicit battery opt-in and caps the lease at five minutes.
- Never export or store Wi-Fi credentials.
- Do not restart an adapter for a failed GitHub, OpenAI, npm, ISP, VPN, or other remote service.
- Do not modify firewall, antivirus, DNS, proxy, network profiles, drivers, TCP/IP configuration, or router settings.
- `guardian network` reads local adapter state and gateway-address presence only. It sends no probes and reveals no network names or address values.
- Use `guardian monitor` for ongoing local interface and route observation. It is bounded to 24 hours (60 minutes by default), refreshes aggregate state at a bounded interval, and does not establish Internet health. Default mode makes no network or power changes. Enable `--auto-reconnect-saved-wifi` only when the user explicitly approves reconnection; it requires 10 seconds of confirmed Wi-Fi disconnection with no default route, makes at most three saved-profile attempts with backoff, and never restarts an adapter.
- Use `guardian network --probe` only when the user asks for a connectivity check. It runs two fixed DNS lookups, reads active route metadata, may send one bounded ICMP echo to a selected gateway per address family, and sends two fixed web requests. It displays summary values only; transient gateway addresses and DNS answers are not displayed or persisted. It writes no probe results to the journal and does not authorize recovery.
- Use `guardian network --reconnect-saved-wifi` only when the user explicitly authorizes reconnecting Wi-Fi. It may change the active connection and submits at most one request through the first existing saved profile in Windows preference order, only after confirmed Wi-Fi disconnection, confirmed absence of an active default route, and a single disconnected wireless interface. It keeps the profile name only in memory; the name may also identify the SSID. It never requests key material. It uses a 20-second Wi-Fi association confirmation window, not Internet access; synchronous Windows queries can extend total command duration. It never restarts an adapter. Respect any explicit user decision to leave Wi-Fi disconnected.
- The explicit reconnect command stores an event UUID, timestamp, and typed outcome in a bounded network journal. Monitor snapshots and probe results are not journaled. Session reports include reconnect outcomes by timestamp interval, not by a causal link to the power lease.
- There is no continuous external connectivity probe, adapter restart, VPN-state detection, or configured remote-service test. The monitor observes local interface/route metadata. ICMP filtering can leave gateway reachability unknown. Classification alone does not change Windows networking; the one-shot and optional monitor reconnect paths require explicit user authorization.
- Never claim that a completed/failed Codex stream can be resurrected. Never replay non-idempotent remote operations automatically.
